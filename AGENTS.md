# Reglas de trabajo del proyecto

- Antes de realizar un cambio grande o importante, revisar el estado de Git y guardar los cambios pendientes del proyecto en un commit de respaldo.
- Si el árbol de trabajo está limpio, identificar el commit HEAD como punto de partida; no crear commits vacíos para simular un respaldo.
- Conservar el repositorio `origin` existente como repositorio de colaboración. No reemplazar su historial ni usar push forzado.
- Trabajar en ramas con prefijo `codex/` salvo indicación distinta del usuario.
- Distinguir entre cambios locales, commits y cambios efectivamente subidos al repositorio remoto al informar los resultados.
- Para la entrega full stack solicitada el 30 de octubre de 2026, trabajar directamente en `main`, según la instrucción expresa del usuario, sin push forzado.
- Agrupar cambios relacionados en incrementos funcionales. Crear cada commit después de implementar y terminar sus pruebas pertinentes; no crear commits por modificaciones mínimas ni para aumentar el historial.
- Conservar las fechas y horas reales de Git. Registrar qué se implementó, corrigió o validó con mensajes descriptivos.
